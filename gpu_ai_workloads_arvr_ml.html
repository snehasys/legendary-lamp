Technical Deep Dive: Context Parallelism for Video Diffusion

Video diffusion models process temporal sequences that exceed single-GPU memory. Context parallelism splits the temporal dimension across GPUs: each GPU handles a subset of frames while maintaining cross-attention to the full sequence via ring-attention communication patterns. The denoising process runs for 50 steps, with each step requiring all-reduce operations across the temporal partition. FP4 precision (native on Blackwell) reduces memory per frame by 4x compared to FP16, enabling longer video generation without proportional GPU scaling.

Easy Questions

Easy
Which technique reduces LLM inference memory footprint while maintaining >99% accuracy?
Correct: C. Quantization reduces memory by 60-75% while maintaining >99.2% accuracy vs FP16 baseline. This is the single most impactful optimization for inference memory constraints. Pipeline parallelism helps throughput but doesn't reduce per-GPU memory for the model itself.
Easy
What is "Continuous Batching" in the context of LLM serving?
Correct: A. Traditional static batching wastes GPU cycles waiting for the longest sequence. Continuous (or "in-flight") batching inserts new requests into available slots as soon as earlier ones finish, boosting GPU utilization from ~35% to ~87%.
Easy
What is the primary advantage of the NVIDIA B200 over the H100 for LLM workloads?
Correct: D. The B200 offers 192GB HBM3e (vs 80GB on H100), 8 TB/s memory bandwidth (vs 3.35 TB/s), and 4,500 FP8 TFLOPS (vs 1,979). This means it can hold larger models and serve them faster. Note: TDP actually increases from 700W to 1,000W.
Q

Medium Questions

Medium
In a 32,000-GPU MoE training cluster, what is the primary infrastructure bottleneck?
Correct: B. MoE models route different tokens to different expert subnetworks, creating massive all-to-all communication patterns. Unlike dense models (which use predictable AllReduce), MoE traffic is irregular and stresses the network fabric. This is why clusters use non-blocking fat-tree topologies with 400Gbps+ InfiniBand or Spectrum-X.
Medium
Why is "Speculative Decoding" particularly effective for reasoning models?
Correct: C. LLM inference is memory-bandwidth bound (not compute-bound) because each token generation requires reading the entire model weights. Speculative decoding uses a small, fast model to propose N tokens, then the large model verifies all N in a single forward pass. This achieves 2-3x speedup because verification is compute-bound (parallel) rather than bandwidth-bound (sequential).
Medium
In Federated Learning for medical imaging, why can't you simply aggregate model weights with a simple average?
Correct: A. Hospital data is highly non-IID—one hospital may see mostly pediatric cases while another sees geriatric. Simple FedAvg causes "client drift" where local models diverge. Advanced algorithms like FedProx, SCAFFOLD, or personalized FL are needed. This is a key nuance interviewers test.

Hard Questions

Hard
Why do Chain-of-Thought reasoning models fundamentally blur the training/inference boundary?
Correct: D. A reasoning model like DeepSeek R1 generates thousands of "thinking" tokens before answering, consuming up to 150x more compute than a standard inference call. This means inference clusters need training-class GPU density, memory, and cooling. The economic model shifts from "cheap inference" to "expensive inference that replaces human reasoning time."
Hard
When serving a 70B model on 4x B200 GPUs with Tensor Parallelism, what determines whether you are compute-bound or memory-bandwidth-bound?
Correct: B. This is a critical nuance. The prefill phase (processing the input prompt) has high arithmetic intensity and is compute-bound. The decode phase (generating tokens one-by-one) has low arithmetic intensity and is memory-bandwidth-bound. Optimal serving requires different strategies for each phase—some systems even disaggregate prefill and decode onto different hardware.
Hard
A video generation model produces 4K@24fps clips. Why does this workload stress GPUs differently than image generation?
Correct: C. Unlike images (single 2D frame), video generation must maintain temporal coherence. This requires 3D attention mechanisms spanning multiple frames, causing attention memory to grow quadratically. A 10-second 4K clip at 24fps = 240 frames, each with millions of tokens. This is why video generation requires 8+ GPUs with NVLink even for inference, and training requires thousands.

Interview Gotchas & Nuances

Common Traps Interviewers Set

  • "Just Add More GPUs" Fallacy: Scaling is NOT linear. Nuance: Always mention Amdahl's Law, communication overhead, and bubble time in pipeline parallelism. For MoE, doubling GPUs may only give 1.6x speedup due to all-to-all bottlenecks.
  • Confusing Inference vs Training Bottlenecks: Nuance: Training is compute-bound (FLOPS matter). Inference decode is memory-bandwidth-bound (GB/s matters). Prefill is compute-bound. Never say "inference needs more FLOPS."
  • Forgetting KV-Cache: When calculating memory for a 70B model, don't just say "70B × 2 bytes = 140GB." Nuance: Add KV-cache: for batch=32, seq_len=4096, it can add 50-100GB. This is often the actual constraint.
  • Ignoring the Prefill/Decode Split: Nuance: Modern systems disaggregate these phases. Prefill nodes are GPU-dense (compute). Decode nodes are memory-dense (bandwidth). Mention this to show depth.
  • "FP8 is Always Better" Myth: Nuance: FP8 training requires loss scaling and can diverge on certain architectures. For inference, INT4 with group quantization often beats FP8 for throughput. Know when each precision is appropriate.

Model Answers: How to Sound Senior

"Design the infrastructure for serving 10,000 LLM requests/second with p99 latency under 200ms." +

Model Answer: "First, I'd characterize the workload: what's the input/output token ratio? For a typical 500-in/200-out pattern, the bottleneck is decode-phase memory bandwidth. I'd use B200s with 8 TB/s HBM3e bandwidth, applying FP8 quantization with INT4 KV-cache to fit the model in fewer GPUs. For 10K RPS, I'd estimate needing ~16 B200 nodes with Tensor Parallelism=4 each, using Continuous Batching and PagedAttention. I'd disaggregate prefill from decode—prefill on compute-optimized nodes, decode on bandwidth-optimized nodes. For the p99 SLA, I'd implement request-level priority queuing and speculative decoding for the decode phase, which gives ~2.3x throughput improvement. Finally, I'd add auto-scaling with a 30-second warm-up buffer."

Why this works: It shows you understand the prefill/decode split, can do back-of-envelope capacity planning, know specific optimizations, and think about tail latency—not just average.

"What makes training a 2T-parameter MoE model different from a 2T dense model?" +

Model Answer: "The key difference is the communication pattern. A dense 2T model uses AllReduce for gradient synchronization—predictable, bandwidth-efficient, and well-optimized by NCCL. An MoE 2T model uses all-to-all communication for token routing, which is irregular, latency-sensitive, and creates hotspots when experts have imbalanced load. This means: (1) the network topology matters more—you need non-blocking fabrics, not just high bandwidth; (2) you need expert-level load balancing (auxiliary losses or capacity factors); (3) the effective compute per token is much lower (only ~8 experts active out of 128), so you get more intelligence per FLOP but the infrastructure cost shifts from compute to networking."

Why this works: It contrasts AllReduce vs all-to-all (shows systems knowledge), mentions load balancing (shows ML knowledge), and frames the cost tradeoff (shows business awareness).

"A customer wants to deploy a 70B model on-premises for GDPR compliance. Walk me through the hardware selection." +

Model Answer: "For a 70B model on-prem, I'd first determine the precision: FP8 gives us ~70GB for weights, plus KV-cache overhead. Option 1: 4x NVIDIA B200 (192GB each, 768GB total) with NVLink for Tensor Parallelism—this gives headroom for large batch sizes and long contexts. Option 2: 8x AMD MI300X (192GB each) if budget is tighter—competitive performance at lower cost per GB. I'd use TensorRT-LLM or vLLM for the serving stack, with Continuous Batching enabled. For GDPR specifically, I'd ensure the inference server has no telemetry, implement request-level encryption at rest, and set up audit logging. The total power budget would be ~4kW for the GPU node, requiring dedicated cooling. ROI breakeven vs cloud is typically 8-14 months at this scale."

Why this works: It shows concrete hardware knowledge (specific GPU models and specs), considers alternatives, addresses the actual business requirement (GDPR), and includes practical concerns (power, cooling, ROI).

"How would you handle a scenario where your video generation model produces temporally inconsistent outputs?" +

Model Answer: "Temporal inconsistency—flickering, object morphing between frames—is the core challenge in video diffusion. I'd approach it at three levels: (1) Architecture: ensure the model uses 3D attention (spatial + temporal) rather than frame-independent 2D attention, so each frame conditions on its neighbors. (2) Training: use temporal discriminators and optical-flow-based consistency losses during training. (3) Inference: implement temporal super-resolution as a post-processing step—generate keyframes first, then interpolate with a dedicated temporal model. The GPU implication is that 3D attention scales quadratically with clip length, so for longer clips I'd use sliding-window temporal attention with overlap, trading some global consistency for tractable VRAM usage."

Why this works: It diagnoses the root cause, proposes solutions at multiple levels (architecture, training, inference), and connects back to GPU resource implications.

What is the maximum acceptable "motion-to-photon" latency in VR before users experience nausea?
Correct: B. The motion-to-photon latency (time from head movement to updated pixels reaching the eye) must be under 20ms to prevent VR sickness. At 90Hz, each frame budget is 11.1ms. This is why cloud rendering is unsuitable for the final frame—network latency alone exceeds the budget.
Easy
What does "foveated rendering" exploit about human vision?
Correct: C. The fovea covers only ~2-5 degrees of visual angle but contains the highest density of cone cells. Outside this region, acuity drops rapidly. AI-driven foveated rendering uses eye-tracking to predict gaze direction and renders only the foveal region at full resolution, saving up to 70% of GPU rendering work.

Medium
What is the primary GPU bottleneck for real-time 3D Gaussian Splatting at 90fps in VR?
Correct: C. Unlike NeRFs (which use neural network inference), Gaussian Splatting is a rasterization workload. Each frame requires depth-sorting and alpha-blending millions of Gaussian primitives. This stresses traditional CUDA cores and memory bandwidth rather than Tensor Cores or RT cores. The RTX 5090's high memory bandwidth (1.8 TB/s) makes it ideal for this.
Medium
Why must Neural SLAM on AR glasses use on-device processing rather than cloud offloading?
Correct: D. AR overlays must be spatially anchored to the real world. If SLAM updates lag by even 30-50ms (typical network round-trip), virtual objects will visibly drift during head movement, breaking the illusion. This forces all SLAM computation onto the device's SoC within a 5-10W power budget.
Medium
How does AI-enhanced passthrough in mixed reality headsets differ from simple camera feed display?
Correct: B. Neural passthrough does far more than display raw camera feeds. It corrects lens distortion, performs stereo depth estimation, fills in regions occluded by the headset's nose bridge, upscales resolution via neural super-resolution, and even predicts future frames to compensate for processing latency—all within an 8ms budget on a mobile SoC.

Hard Questions

Hard
A "World Generation" system (like Genie 3) creates navigable 3D environments from text. Why does this require fundamentally different GPU resources than text-to-image generation?
Correct: A. World generation combines the challenges of: (1) generative AI (diffusion/autoregressive models for content creation), (2) 3D consistency (maintaining coherent geometry as the user moves), (3) real-time rendering (24+ fps output), and (4) physics simulation (objects must behave realistically). Why is gaze prediction (predicting where the user will look 20-40ms in the future) essential for foveated rendering, and what makes it an AI problem?
Correct: C. Even with perfect eye tracking, there's a 20-40ms delay between detecting gaze and displaying the rendered frame. During a saccade (rapid eye movement), the eye can move 30+ degrees in 50ms. Without prediction, the high-resolution foveal region would lag behind actual gaze. Neural networks trained on eye movement patterns predict the gaze target before the saccade completes, allowing pre-rendering of the correct region.

Interview Gotchas & Nuances

Critical Mistakes to Avoid

  • Suggesting Cloud Rendering for VR: Never propose cloud-based final frame rendering for VR/AR. Nuance: The 20ms motion-to-photon budget makes network round-trips impossible. Cloud can assist with asset generation, world building, or AI model updates—but the final render must be local.
  • Confusing NeRF and Gaussian Splatting: Nuance: NeRFs use neural networks (Tensor Cores, slow per-pixel) for novel view synthesis. Gaussian Splatting uses explicit 3D primitives (rasterization, fast per-frame). They solve similar problems but have completely different GPU profiles. Know which to recommend for real-time vs offline.
  • Ignoring Thermal Constraints: Nuance: A standalone VR headset has ~8-12W total power budget. You cannot run a 700W data center GPU. Always mention quantization (INT8/INT4), model distillation, and NPU offloading when discussing on-device AI.
  • Forgetting Stereo Rendering: Nuance: VR renders TWO eyes, not one. This doubles the pixel count (or requires multi-view rendering tricks). When calculating GPU requirements, always account for stereo. A "4K per eye" headset is rendering 8K total.
  • Underestimating SLAM Complexity: Nuance: Neural SLAM isn't just "running a CNN on camera frames." It involves loop closure detection, map optimization, semantic labeling, and persistent storage—all within 16ms on a mobile chip. The memory management alone is a significant engineering challenge.

"Compare NeRF and Gaussian Splatting for a VR telepresence application. Which would you choose and why?" +

Model Answer: "For real-time VR telepresence at 90fps, I'd choose 3D Gaussian Splatting. Model Answer: "Object drift in AR means the SLAM system is losing tracking accuracy. Q

Easy Questions

Easy
Why are AI weather models (like GraphCast) 10,000x more energy-efficient than traditional numerical weather prediction?
Correct: D. Traditional NWP solves the Navier-Stokes equations on a 3D grid—computationally massive. AI weather models learn the mapping from current atmospheric state to future state directly from ERA5 reanalysis data, producing a 10-day forecast in ~90 seconds on a single GPU vs hours on a supercomputer. The energy difference is ~1 kWh vs ~10 MWh.
Easy
What type of GPU precision is most critical for molecular dynamics simulations in drug discovery?
Correct: B. Molecular dynamics simulates atomic interactions where tiny force errors accumulate over millions of timesteps. FP64 (double precision) is essential for numerical stability in these simulations. This is why scientific HPC GPUs (H100/H200 with strong FP64) are preferred over inference-optimized chips that sacrifice FP64 for INT8/FP8 throughput.
Q

Medium Questions

Medium
How does AlphaFold3 differ from AlphaFold2 in terms of GPU workload characteristics?
Correct: A. AlphaFold3's shift to a diffusion-based architecture means each prediction requires multiple denoising iterations (like image generation), increasing GPU compute per structure. However, it gains the ability to predict complexes (protein + DNA + ligand + ions), making it far more useful for drug discovery where binding interactions matter.
Medium
Why can AI climate models simulate 1,000 years of climate in 12 hours, when traditional models take months for the same period?
Correct: C. Traditional climate models solve coupled differential equations (atmosphere, ocean, ice, land) at time steps of minutes, requiring billions of sequential calculations. AI climate models learn the state-to-state transition function and can take much larger effective time steps (hours or days), parallelized on GPUs. The University of Washington demonstrated this with their "Climate in a Bottle" approach.
Q

Hard Questions

Hard
What is the key limitation of AI weather models that prevents them from fully replacing traditional NWP systems?
Correct: D. AI weather models are trained on historical data (ERA5, ~40 years). Extreme events are rare in this dataset, causing the models to "regress to the mean" for unusual situations. Additionally, unprecedented events (new volcanic eruption, novel climate regime) have no training signal. Traditional physics-based models handle these better because they solve fundamental equations that generalize to unseen conditions. This is why operational weather services run both in parallel.

Interview Gotchas & Nuances

Scientific AI Interview Traps

  • "AI Replaces Physics" Myth: Nuance: AI models complement, not replace, physics-based simulation. For drug discovery, AI identifies candidates but MD simulation validates them. For weather, AI provides fast forecasts but physics models handle extreme events. Always frame AI as accelerating the pipeline, not eliminating physics.
  • Precision Requirements: Nuance: Scientific computing often needs FP64, unlike ML which uses FP8/FP16. Don't recommend inference-optimized GPUs (which sacrifice FP64) for MD simulations. The H200 and MI300A have strong FP64; the B200's FP64 ratio is lower.
  • Validation vs Accuracy: Nuance: In drug discovery, a model that's 95% accurate on average but misses 5% of toxic compounds is dangerous. Always discuss validation methodology, not just accuracy metrics. Mention ensemble approaches and uncertainty quantification.
  • Data Scarcity in Science: Nuance: Unlike internet-scale text/image data, scientific datasets are small and expensive to generate. A drug discovery dataset might have only 10,000 compounds with measured binding affinities. This fundamentally changes the ML approach (few-shot learning, physics-informed priors, active learning).

Model Answers for Scientific AI Interviews

"How would you design a GPU-accelerated drug discovery pipeline from target identification to lead optimization?" +

Model Answer: "I'd design a five-stage GPU pipeline: (1) Target identification: use genomics AI models on L40S GPUs to identify disease-relevant protein targets from patient data. (2) Structure prediction: run AlphaFold3 on B200 GPUs to predict the 3D structure of the target protein and its binding sites—this uses diffusion-based inference requiring multiple denoising steps. (3) Virtual screening: screen 10 billion compounds against the predicted binding site using GPU-accelerated docking (AutoDock-GPU) on a cluster of L40S GPUs—this is embarrassingly parallel and throughput-optimized. (4) MD simulation: for the top 1,000 hits, run molecular dynamics on H200 GPUs (FP64 required) to validate binding affinity and assess off-target effects. (5) Generative optimization: use a generative chemistry model to propose novel molecules optimized for the binding pocket, ADMET properties, and synthesizability. Total time: ~6 months vs 3+ years traditionally. The key GPU insight is that each stage has different precision and compute requirements—you can't use one GPU type for everything."

Why this works: It shows end-to-end pipeline thinking, matches specific GPUs to each stage's requirements, and quantifies the speedup vs traditional approaches.

"Should a national weather service replace their supercomputer with GPU-based AI weather models?" +

Model Answer: "Not replace—augment. I'd recommend a hybrid strategy: (1) Deploy AI weather models (GraphCast/Pangu-Weather) on a small GPU cluster (64x B200) for rapid ensemble forecasting—producing 50-member ensembles in 75 minutes vs 50+ hours traditionally. This enables much more frequent forecast updates (every 15 minutes vs every 6 hours). (2) Maintain the traditional NWP system for: extreme event forecasting where AI models underperform due to training data scarcity, providing ground truth for AI model validation, and handling novel atmospheric conditions (volcanic eruptions, unprecedented climate states). (3) Use AI for downscaling: take the coarse NWP output and use a super-resolution model to produce 5km local forecasts. The economic case is compelling: the GPU cluster costs ~$2M vs $100M+ for a new supercomputer, while providing 100x faster forecasts for routine weather. But the physics-based system remains essential for safety-critical severe weather warnings."

Why this works: It avoids the binary "replace vs keep" trap, proposes a nuanced hybrid strategy, quantifies the economics, and identifies where each approach excels—showing mature engineering judgment.

Key Insight: The Bimodal GPU Landscape

Post-2024 GPU workloads cluster into two distinct regimes: (1) Frontier Training requiring 1,000-32,000+ GPUs running for weeks/months with throughput optimization, and (2) Edge/Real-time Inference requiring 1-8 GPUs with sub-10ms latency constraints. The middle ground (10-100 GPUs) is increasingly rare, as workloads either scale to frontier or compress to edge. AR/VR workloads exclusively occupy the edge regime, while ML training pushes ever further into the frontier regime.
